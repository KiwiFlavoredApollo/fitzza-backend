## 사용자 확정 범위

- 오늘은 코드·이미지·권한·정지 Job 배포만 수행한다.
- 실제 수집·Jev 호출·임베딩·Qdrant 적재·서비스 중단은 별도 실행 지시가 있어야 한다.
- 내일을 가리키는 run ID는 예약 실행이 아니다. 모든 신규 Job은 suspend=true, 실행 승인 옵션도 없는 상태로 유지한다.
- 기존 로컬 500개를 seed 후보로 보존하고, 부족분 신규 수집은 클라우드에서 한다.
- 클라우드 수집 → 품질·선정 → Jev 정제 → 로컬 사람 검수 → 승인본 업로드 → 클라우드 임베딩·Qdrant staging 적재.

## 수량 기준

기존 후보 500 JSON은 고유 ID 500개, 중복 0개, 카테고리별 100개다.
Jev 입력 검사에서는 색상 매핑 상품 500개·고유 색상 이름 299개를 확인했다.
이는 품질 검수 완료 증거가 아니다.

| 카테고리 | 최종 목표 | seed 통과 시 추가량 |
| --- | --- | --- |
| 상의 | 900 | 800 |
| 하의 | 750 | 650 |
| 신발 | 600 | 500 |
| 아우터 | 450 | 350 |
| 모자 | 300 | 200 |
| 합계 | 3000 | 2500 |

탈락한 seed만큼 추가량을 다시 계산한다. 남성/공용·실측 필수와 의류 계절 균형을 유지한다.

## 소스 확정과 안전장치

- AI 담당자 테스트 완료 후 사용자가 feat/color-map-jev 또는 feat/docker-qdrant-data를 승인했다.
- 두 브랜치의 scripts/index_to_qdrant.py는 동일하며 기준 SHA는 1568de39e17cde9fb229b30f78b53f80b2a891f5다.
- 기존 스냅샷을 자동 복원하는 Dockerfile은 EKS에 적용하지 않는다.
- 인덱서: staging 전용·기존 컬렉션 삭제 금지·이미지 4개씩 처리·완료 수량 확인·승인본 검사.
- 색상 승인과 데이터 품질 승인은 분리한다. 기존 overrides도 사람이 확인한 것으로 간주하지 않는다.
- 모델은 품질 승인 manifest에서 revision을 고정한다. 배포 중 모델 가중치를 다운로드하거나 추론하지 않는다.
- Jev 키는 사용자 등록 완료. SSM SecureString version 1 메타데이터만 확인했으며 값 조회·Jev 호출은 하지 않았다.
- 앱·CD 역할은 변경하지 않는다. 크롤러·Jev·인덱서 서비스 계정과 입력/출력 경로 권한을 분리한다.

- 유지보수·복구 계획 재확인 후 별도 승인된 실행 시간 안에서 단계별 실제 검증.
- 전체 자동 오케스트레이션(FITZZA-219)과 3000개 적재·검색 검증은 아직 미완료.
